Projects & Architecture
Analytics Engine
Vantix — Real-Time OLAP Analytics Platform

ClickHouse-backed analytics layer replacing PostgreSQL OLAP for hospital dashboards. 10x query acceleration, CDC-driven data freshness under 1 second.

ClickHouse Debezium Spring Boot AWS ECS

Problem

Hospital dashboards at Semmel Health ran on a PostgreSQL OLAP layer. As the dataset grew to tens of millions of clinical events, dashboard queries degraded from sub-second to 8–12 seconds — unacceptable for real-time patient monitoring. Scaling PostgreSQL read replicas was cost-prohibitive and didn't address the root cause: row-oriented storage is fundamentally wrong for analytical queries.

Architectural Decisions

DecisionChosenRejectedRationale
OLAP Storage ClickHouse Redshift, BigQuery Self-hosted, sub-ms column scan latency, no per-query cloud cost
CDC Mechanism Debezium + Kafka Polling / triggers WAL-level capture ensures consistency; zero-impact on source DB
Sync Latency Target < 1 second Nightly batch Operational dashboards require near-real-time clinical data

Outcomes

Production Impact

10x query acceleration (avg 9s to 0.9s). Data freshness under 1 second via CDC. Zero dashboard downtime during migration. PostgreSQL OLAP instance retired, saving $800/month in RDS read-replica costs.

AI Platform
AI Trend Intelligence & Instant Costing

Replaced 15-day manual fashion R&D cycles with OpenAI semantic search over ClickHouse. 80% cycle reduction, 100% UAT acceptance on first release.

OpenAI Embeddings Elasticsearch ClickHouse FastAPI

Problem

Fashion buyers at Nitex manually cross-referenced trend reports, supplier costing sheets, and historical style data — a 15-day process per collection cycle. No structured data store existed for vector similarity queries across hundreds of thousands of product styles.

Solution Architecture

  • Generated OpenAI text-embedding-3-large vectors for all product styles and trend reports
  • Stored embeddings in Elasticsearch with cosine similarity indexing for semantic search
  • PostgreSQL CDC pipeline (Debezium) syncs product catalogue changes to Elasticsearch within milliseconds
  • ClickHouse powers the costing analytics layer — aggregating supplier pricing across millions of rows in < 500ms
  • FastAPI orchestrates the search + costing pipeline with async concurrency

Outcomes

Production Impact

15-day cycle compressed to 3 days (80% reduction). 100% UAT acceptance on first production release. Semantic search precision exceeded keyword search by 340% on buyer satisfaction score. Zero data discrepancy in warehouse-to-retail inventory tracking.

Clinical Microservice
SafetyOS — Hospital Audit & Surveillance Engine

Event-driven clinical audit microservice on Spring Boot + PostgreSQL CDC. 5x throughput over the legacy batch system. Zero-trust AWS VPC deployment.

Spring Boot PostgreSQL CDC AWS SSM ElastiCache

Problem

The legacy audit system processed patient safety events in nightly batches — meaning clinical teams had no intraday visibility into safety protocol violations. In a hospital setting, a 24-hour audit lag is a patient safety risk.

Solution

  • Replaced batch with a CDC-driven event stream using Debezium on PostgreSQL WAL
  • Spring Boot microservice processes audit events in real time with idempotent event handlers
  • Deployed in a zero-trust AWS VPC — all inter-service calls via AWS SSM (no public endpoints)
  • ElastiCache Redis for audit rule caching — eliminates DB round-trips on hot compliance rules
  • Composite indexing strategy on patient ID + timestamp reduces query time by 70%

Outcomes

Production Impact

5x throughput vs the legacy batch system. Audit lag reduced from 24 hours to under 30 seconds. Zero security incidents since zero-trust deployment. Sub-minute CI/CD pipelines via GitHub Actions.

Telecom Backend
Robi Axiata — Nationwide SIM Distribution Backend

Real-time inventory sync across thousands of retail points for Bangladesh's second-largest telecom operator. +30% SIM sales volume, zero discrepancy audit.

Spring Boot PostgreSQL RabbitMQ Redis

Problem

Manual SIM inventory reconciliation caused stock-outs at high-demand retail points and over-stocking at low-demand locations — directly suppressing sales. The existing system had no real-time visibility; stock counts were only updated on end-of-day batch runs.

Solution

  • Spring Boot microservice with event-driven inventory updates via RabbitMQ
  • Redis cache for hot stock-level reads — eliminates DB bottleneck at peak query times
  • PostgreSQL with optimised composite indices for warehouse-to-retail lineage queries
  • REST API consumed by thousands of distributor mobile clients simultaneously

Outcomes

Production Impact

+30% SIM sales volume uplift attributable to real-time stock visibility. Zero data discrepancy on first warehouse-to-retail inventory audit. System handles peak load of thousands of concurrent distributor clients.
